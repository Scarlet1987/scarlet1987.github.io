How the front end is put together

Plain words
  • Login is local. Pick a person, enter a PIN. No email, no password reset on a website, no server to be down.
  • One face, everywhere. Login, HUD and installer are the same HTML and the same sage / deep-green panels — not three different programs.
  • Preview is the face. The webview talks to the Rust engine over local HTTP on the machine itself, so what you preview is what ships.
  • First run is separate. The 8-step setup (backup first, USB before install) only runs before the first login exists.
  • Less at once. FF13-style HUD, streamlined — show the next thing, not everything.
Tap / PIN→HTML Face→Orchestrator (Rust)→Engine (Rust)→Your hardware

The orchestrator is the rock in the middle: if one piece inside fails, it contains the failure — one broken node never takes the whole face down. That’s exactly what the workspace below lets you see.

3 — Put it on metal. Make the software real.

Read-back: The graph above isn’t just a drawing — it’s the build list. When Run is green, this is the order it lands on a real machine: Tiny Core underneath, Rust in the middle, HTML face on top. USB first, install second — backup before either.

TOP · HTML Face — this page, word for word↕ local HTTPMIDDLE · Rust Orchestrator + Rust Engine↕BOTTOM · Tiny Core Linux→ YOUR HARDWARE
Step 0 · First
Back up

Real choice on first run: back up, or skip — skipping locks the Windows-wipe door. Nothing gets wiped without this step.

Step 1 · Build
Run the graph green

Press Run above. Every node in your graph has to pass. A red node is the break — fix it here, not after it’s on metal.

Step 2 · Export
Download the build manifest

One file listing every node, wire, and layer in order. That’s the recipe the USB / installer follows — nothing hidden, nothing extra.

Step 3 · USB first
Make a bootable USB

The installer writes the image to a plugged-in stick. Boot from USB and live-test it. The live run is held to the install bar, not a demo bar.

Step 4 · Benchmark
First-run check on that PC

8-step first run: drivers are chosen, not shipped blind. Benchmark proves this hardware can do the work before anything installs.

Step 5 · Land it
Choose how it lands

Keep the USB, install directly to metal, or — only if you backed up — wipe Windows. One tap at a time, your choice at the end.

This page can’t flash a USB or install an OS from inside a browser — no page can, honestly. What it does is give you the exact, checked build list to take to the real Tiny Core sandwich build. When that build runs, this face moves over word for word, line for line.

Face nodes are what people see

Login, HUD panels, installer steps. If a face node fails on Run, the break is in the pretty part — the engine underneath may still be fine.

The orchestrator holds the shape

It decides how pieces talk and what survives a restart. Inner pieces can be swapped or rebuilt; the master shape stays stable — the nesting-doll rule.

Tables, not live simulation

Data nodes are lookup tables: compute once, save the map, then move data. That’s why it stays light and fast on ordinary hardware.
