How the front end is put together

Plain words
  • Login is local. Pick a person, enter a PIN. No email, no password reset on a website, no server to be down.
  • One face, everywhere. Login, HUD and installer are the same HTML and the same sage / deep-green panels — not three different programs.
  • Preview is the face. The webview talks to the Rust engine over local HTTP on the machine itself, so what you preview is what ships.
  • First run is separate. The 8-step setup (backup first, USB before install) only runs before the first login exists.
  • Less at once. FF13-style HUD, streamlined — show the next thing, not everything.
Tap / PIN→HTML Face→Orchestrator (Rust)→Engine (Rust)→Your hardware

The orchestrator is the rock in the middle: if one piece inside fails, it contains the failure — one broken node never takes the whole face down. That’s exactly what the workspace below lets you see.

3 — Starter tutorial. Learn the board by doing it.

Start here if the board is new to you. Each card below is one job, in plain words — how you connect, how you delete, how the pop out functions, and the rest. Every card has a Try it button that takes you straight to the board above, so you can do it while you read it. Work through them in any order; come back any time.

Wiring

This is how you connect

Every node has two dots: an input dot on its left and an output dot on its right. A wire always goes out of one node and into the next — that direction is the order things run in.

  1. Click the output dot (right side) of the first node. It fills green and glows — that output is now armed.
  2. Click the input dot (left side) of the next node. The wire draws itself between them and the log confirms it.
  3. That’s the connection. Repeat to chain more: face → orchestrator → engine.
Login face— wire —>Orchestrator

A node can’t wire to itself, and the same wire can’t be made twice — the board just tells you in the log. Changed your mind mid-wire? Click a different output dot and the armed dot moves there.

Removing things

This is how you delete

Deleting is always select first, then delete — so you can see exactly what’s about to go.

  • A node: click the node so it gets the green outline, then press Delete on the keyboard — or use Delete node in the inspector on the right. Its wires go with it.
  • One wire only: click the wire itself — it turns red — then press Delete. Both nodes stay.
  • Every wire: Clear wires in the toolbar removes all the wiring and keeps the nodes, ready to rewire.
  • In the pop-out window: Wipe selection clears just the selected node or wire; Clear board wipes the whole board in one tap.

Deleted something by mistake? Reload the example with Load Red Queen example in the toolbar to get the starter graph back.

Second window · second monitor

This is how the pop out functions

Pop out gives the board its own window, so you can drag it onto a second monitor and keep the tools in front of you here.

  1. Tap ⧉ Pop out — own window in the toolbar above the board.
  2. A new window opens showing just the board — nodes, wires, Run, Fit, Wipe selection and Clear board. The Creator, palettes and inspector stay in this main window; that split is on purpose.
  3. The two windows are the same live graph: arrange, wire, delete or Run on either side and it shows up on both. Nothing is copied — it’s one board in two places.
  4. Close the pop-out window whenever you like. The graph stays safe here in the main window.

If your browser blocks the new window, the board opens in Focus instead — the workspace fills this screen — and the log tells you. Allow pop-ups for this page and Pop out will open its own window next time.

Adding things

This is how you add a node

Two ways, both above the board:

  • Quick add: tap a button in the QUICK ADD row — Face panel, Orchestrator, Rust engine, Data table, Benchmark / check — and the node lands on the board, already selected.
  • Node Creator (the Maker): name your own node, pick what kind of piece it is, say in plain words what it does, then + Create node → canvas. Templates like Mic button and Failure guard fill the form in for you.

Drag a new node by its coloured top bar to move it, then wire it in — output dot to input dot.

Proving it works

This is how you run it

▶ Run graph walks the wires in order and each node reports back underneath its name:

  • IDLE — not run yet. RUNNING — its turn. DONE — passed.
  • FAIL — that’s the break. A node whose input failed is skipped and marked, and the log under the board says where it stopped — the rest of the face stays up.
  • Step once runs one node per tap, if you want to watch it slowly. Reset status puts every node back to idle.

If the log says there’s a loop in the wires, a wire circles back on itself — delete one wire in the circle and run again.

Getting around

Moving, zooming, resizing

  • Move a node: drag it by its coloured top bar.
  • Move around the board: drag empty board to pan.
  • Zoom: the − / + buttons, Ctrl + scroll, or Fit graph to see everything at once.
  • More room: Wide view hides the inspector, Taller canvas grows the board downward, the drag strip under the board resizes it by hand, and Focus fills the whole screen (Esc to come back).
  • See a node’s details: click it — the inspector on the right shows its name, kind, what it does, and its last run status, all editable.

When you’re ready: put it on metal

The graph isn’t just a drawing — it’s the build list. When Run is green, download the build manifest: one file listing every node, wire and layer in run order. That file is the recipe for the real build — back up first (skipping a backup locks the Windows-wipe door), write the Tiny Core sandwich to a bootable USB and live-test it at the install bar, run the first-run check on the target hardware, then choose how it lands: keep the USB, install directly to metal, or — only with a backup — wipe Windows.

Face nodes are what people see

Login, HUD panels, installer steps. If a face node fails on Run, the break is in the pretty part — the engine underneath may still be fine.

The orchestrator holds the shape

It decides how pieces talk and what survives a restart. Inner pieces can be swapped or rebuilt; the master shape stays stable — the nesting-doll rule.

Tables, not live simulation

Data nodes are lookup tables: compute once, save the map, then move data. That’s why it stays light and fast on ordinary hardware.
