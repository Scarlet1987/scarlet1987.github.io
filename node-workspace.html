How the front end is put together

Plain words
  • Login is local. Pick a person, enter a PIN. No email, no password reset on a website, no server to be down.
  • One face, everywhere. Login, HUD and installer are the same HTML and the same sage / deep-green panels — not three different programs.
  • Preview is the face. The webview talks to the Rust engine over local HTTP on the machine itself, so what you preview is what ships.
  • First run is separate. The 8-step setup (backup first, USB before install) only runs before the first login exists.
  • Less at once. FF13-style HUD, streamlined — show the next thing, not everything.

The orchestrator is the rock in the middle: if one piece inside fails, it contains the failure — one broken node never takes the whole face down. That’s exactly what the workspace below lets you see.

3 — Starter tutorial. Learn the board by doing it.

Start here if the board is new to you. Each card below is one job, in plain words — how you connect, how you delete, how the pop out functions, and the rest. Every card has a Try it button that takes you straight to the board above, so you can do it while you read it. Work through them in any order; come back any time.

Wiring

This is how you connect

Every node has two dots: an input dot on its left and an output dot on its right. A wire always goes out of one node and into the next — that direction is the order things run in.

  1. Click the output dot (right side) of the first node. It fills green and glows — that output is now armed.
  2. Click the input dot (left side) of the next node. The wire draws itself between them and the log confirms it.
  3. That’s the connection. Repeat to chain more: face → orchestrator → engine.
Login face— wire —>Orchestrator

A node can’t wire to itself, and the same wire can’t be made twice — the board just tells you in the log. Changed your mind mid-wire? Click a different output dot and the armed dot moves there.

Removing things

This is how you delete

Deleting is always select first, then delete — so you can see exactly what’s about to go.

  • A node: click the node so it gets the green outline, then press Delete on the keyboard — or use Delete node in the inspector on the right. Its wires go with it.
  • One wire only: click the wire itself — it turns red — then press Delete. Both nodes stay.
  • Every wire: Clear wires in the toolbar removes all the wiring and keeps the nodes, ready to rewire.
  • In the pop-out window: Wipe selection clears just the selected node or wire; Clear board wipes the whole board in one tap.

Deleted something by mistake? Reload the page to get the starter graph back.

Second window · second monitor

This is how the pop out functions

Pop out gives the board its own window, so you can drag it onto a second monitor and keep the tools in front of you here.

  1. Tap ⧉ Try it — pop the board out now at the bottom of this card.
  2. A new window opens showing just the board — nodes, wires, Run, Fit, Wipe selection and Clear board. The Creator, palettes and inspector stay in this main window; that split is on purpose.
  3. The two windows are the same live graph: arrange, wire, delete or Run on either side and it shows up on both. Nothing is copied — it’s one board in two places.
  4. Put it back when you’re done — the button lives in both places. Tap ↩ Put back — return to main window in the pop-out window itself, or tap ↩ Put back in Window tools here in the main window. Either one closes the pop-out window and returns you to the main window. The graph stays safe and unchanged here.

If your browser blocks the new window, the board opens in Focus instead — the workspace fills this screen — and the log tells you. Allow pop-ups for this page and Pop out will open its own window next time.

Proving it works

This is how you run it

▶ Run graph walks the wires in order and each node reports back underneath its name:

  • The face preview opens. Tapping Run also opens the face preview in its own pop-out window, like the breadboard: your graph laid out as the face — the login screen on top, Group 1’s panels in the middle, the HUD face at the bottom — lighting up live as the graph runs, same run, same real numbers (the engine panel shows the real health that came back). Amber is running, green is passed, red is the break. Close it from its own Close preview button, or with Close face preview in Run tools here. If your browser blocks the window, the run still happens here and the log says so.
  • Rust engine does real work. When a Rust engine pocket runs, it asks the real Rust orchestrator on this machine — GET http://127.0.0.1:7790/api/health — for the engine’s real health. A real ok passes the pocket; degraded or engine_failed fails it, and the log shows the real pid, restarts, failures, queue depth and uptime that came back. If the orchestrator isn’t reachable, the log says so plainly and that pocket plays the demo instead, so the board still works with nothing running. The other pockets still run as demo steps for now.
  • IDLE — not run yet. RUNNING — its turn. DONE — passed.
  • FAIL — that’s the break. A node whose input failed is skipped and marked, and the log under the board says where it stopped — the rest of the face stays up.
  • Run by node runs one node at a time — one step per tap, if you want to watch it slowly — and the button names the next node before you tap it, like “Run by node — 2 of 3: Group 1 — 4 pockets in sequence”. A group is one step: one tap runs all its pockets. The first tap resets the board to idle before step 1, and the log says so when it happens. Reset status (in Window tools) puts every node back to idle.
  • Not wired — stays idle. Run only walks the wires. If there are no wires at all, Run stops right there and nothing turns done. If only some nodes are unwired, those stay idle and the log names them as not wired — wire them in and run again.

If the log says there’s a loop in the wires, a wire circles back on itself — delete one wire in the circle and run again.

Grouping · like draw.io

This is how you group nodes

Pick a few nodes and put a frame around them — the frame moves as one piece, and the group itself works like a node. The nodes inside are data pockets: they are not wired to each other. The group holds the data, and the group tells the program to run the pockets in sequence.

  1. Pick: hold Ctrl (or Shift) and click each node you want — picked nodes get a dashed green outline. Or hold Shift and drag a box on empty board around them.
  2. Group: tap ▣ Group selected in the toolbar. A framed group appears around them with its own name bar. Any wires between the picked nodes come off — pockets inside a group are unwired by design, because the group holds their data.
  3. Move it: drag the group’s dark name bar — or drag any node inside it — and the whole group moves together.
  4. Resize it: drag the grip in the frame’s bottom-right corner to resize the group by hand — give it more room without moving a single pocket; only the frame grows. The frame never shrinks smaller than its pockets. Double-click the grip to snap back to the snug fit.
  5. Wire it: the frame has the same dots as a node — an input dot on its left and an output dot on its right. Wire into the group and out of the group just like any other node. There are no wires between the pockets inside — the group holds their data, so they don’t need any, and the board won’t let you draw one.
  6. Run it: press ▶ Run graph. When the group’s turn comes, the group runs its pockets in sequence, as one step — in the order they were picked into the group, listed numbered in the inspector when the group is selected. The frame shows RUNNING, then DONE or FAIL, and the log names the group and each pocket as it runs. If the group holds a Switch, the switch runs the group until it is all passed, and that pass is learned and stored as the group’s sequence — only then does the group’s out fire — see the switch card below.
  7. Step it: Run by node counts a group as one step too, but the button says so before it happens — “Run by node — 2 of 3: Group 1 — 4 pockets in sequence” — so one tap running the whole set is never a surprise.
  8. Ungroup: click the group’s frame to select it, then tap ▢ Ungroup. The frame goes away and the pockets stay exactly where they are — there are no inside wires to keep, because pockets were unwired. Wires that went to the group itself are removed — rewire to the nodes directly if you still need them.

A node can only be in one group at a time — grouping a node that’s already grouped moves it into the new group. Deleting a node inside a group just takes that node out; if only one node is left, the frame lets go on its own.

The gate inside the group

This is how the switch works

The hard spot in a group is the sequence — the pockets hold code, but nothing says when the group is done. That job belongs to one Switch node, placed inside the group with its pockets. The switch is just there to run the group until the group is all passed.

  • 8 ins, 1 out. The switch has eight numbered input dots down its left side and one output dot on its right. Outside a group, wire up to 8 pockets into its ins, one per dot. Inside a group the pockets are unwired, so the switch doesn’t need their wires — it takes each pocket’s result as it runs them in sequence.
  • It runs the group. On Run, the switch runs its pockets in sequence, one after the next, collecting each result on its ins — and it keeps the group running until every pocket has passed. It is the driver and the gate, not another pocket in line.
  • A pass is learned and stored. When the whole group passes, that pass means the sequence: the order the pockets just ran in is learned and stored on the group — the frame and the inspector say “sequence learned · stored”, and the next run follows the stored sequence. Only then does the switch fire its one out: an ALL PASS.
  • Fail → the switch finds the pocket. If a pocket doesn’t pass, the switch holds the signal, names the pocket that failed in the log, and the out does not fire — and no sequence is stored, because there was no pass to learn from.
  • The out goes where the group goes. The ALL PASS leaves through the group’s output dot to whatever the group is wired to — the HUD face output, or any other output the group is connected to. The switch never picks the destination; the group’s wire does.

Add a switch from QUICK ADD or the Maker template, then pick it together with its pockets and tap ▣ Group selected. A group can hold up to 8 pockets on one switch — that’s what the 8 ins are for.

When you’re ready: put it on metal

The graph isn’t just a drawing — it’s the build list. When Run is green, download the build manifest: one file listing every node, wire and layer in run order. That file is the recipe for the real build — back up first (skipping a backup locks the Windows-wipe door), write the Tiny Core sandwich to a bootable USB and live-test it at the install bar, run the first-run check on the target hardware, then choose how it lands: keep the USB, install directly to metal, or — only with a backup — wipe Windows.

Face nodes are what people see

Login, HUD panels, installer steps. If a face node fails on Run, the break is in the pretty part — the engine underneath may still be fine.

The orchestrator holds the shape

It decides how pieces talk and what survives a restart. Inner pieces can be swapped or rebuilt; the master shape stays stable — the nesting-doll rule.

Tables, not live simulation

Data nodes are lookup tables: compute once, save the map, then move data. That’s why it stays light and fast on ordinary hardware.
