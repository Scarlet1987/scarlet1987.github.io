The mission
Preview → GitHub → Stable → Build.

Every build follows the same law: nothing gets packaged until it's been clicked through in the browser and called stable. The harness runs light in RAM and dies clean — no disk litter, no surprises at install time.

What got removed — and why

The homepage was chaos when all I wanted was to navigate and work. So the chaos goes.

✕Activity feed

"X starred Y", "Z pushed to…" — I'm here to work, not watch a social timeline. If I want updates, I'll open the repo.

✕"Explore repositories"

Guessing what I might like is noise. I know my own projects — I don't need a recommendation engine on my own page.

✕Trending sidebar

Trending is someone else's priorities sitting on my page. My page should be about my work.

✕Eight-tab clutter

Overview, Projects, Packages, Stars, Sponsors… Four tabs that earn it: the projects that matter, everything else, one-click downloads, and fork history. Navigation I have to learn is work I'm not doing.

+Executables tab

Downloads shouldn't be a scavenger hunt through Releases. One tab, one button per platform, done.

+Fork history kept

The one bright spot in the old UI — knowing where a project came from. Kept as its own tab: who forked from whom, what's different, no graph spaghetti.

The rule: "If it doesn't make sense to the user the user will either complain or ignore it." — every element on this page earned its place.
